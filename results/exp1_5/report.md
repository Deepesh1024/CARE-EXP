# Linearization Gap Analysis of Pre-Merge Expert Similarity Features for Mergeability Prediction in Mixture-of-Experts Language Models

---

# Abstract

Expert merging in Mixture-of-Experts (MoE) language models requires predicting which expert pairs can be safely merged without degrading model performance. Experiment 1 of the CARE (Capability-Aware Redundancy Elimination) research program established that no single handcrafted similarity metric reliably predicts oracle merge quality as measured by KL divergence. This motivates Experiment 1.5, which investigates whether combining multiple weak pre-merge proxy features can collectively explain oracle merge quality.

We construct a strict disjoint expert split to prevent identity leakage and train four regression families—Linear Regression, Ridge, LASSO, and XGBoost—across three feature variants of increasing complexity. The best linear model (LASSO) achieves a Spearman rank correlation of ρ = 0.484 against the oracle, while the best nonlinear model (XGBoost) achieves ρ = 0.593, yielding a **linearization gap of Δ = +0.109**. Critically, all models exhibit near-zero or negative R² on the test set, indicating that the existing seven pre-merge features explain negligible variance in oracle KL divergence.

During this experiment, we discovered that six features previously considered candidates—including CrossEntropy_Delta—are in fact **oracle-grade features** that require the actual merge-and-evaluate loop, disqualifying them as lightweight pre-merge predictors. After their removal, the linearization gap nearly doubled from preliminary estimates, revealing that the true predictive ceiling of the current feature family is substantially lower than initially believed. These findings unambiguously establish that new capability-aware features must be designed (Experiment 2) before CARE can function as a practical pre-merge estimator.

---

# 1. Research Question

**Primary Question:** Can multiple weak expert similarity metrics, when combined through multivariate regression, collectively predict oracle merge quality (Oracle KL divergence) for expert pairs in a Mixture-of-Experts language model?

**Secondary Question:** How large is the gap between the best linear and best nonlinear combination of these features—i.e., the *linearization gap*—and what does this gap imply about the representational sufficiency of the current feature space?

---

# 2. Motivation

Experiment 1 of the CARE research program evaluated seven handcrafted similarity metrics individually against Oracle KL divergence across multiple calibration sizes (N = 64, 128, 256) and network depths (first, middle, last layers). The central finding was negative: **no single metric consistently predicts merge quality.** Every metric exhibited success only under narrow conditions—specific layers or calibration sizes—and failed to generalize across the full experimental grid.

This result has two possible interpretations:

1. **Interpretation A (Feature Sufficiency):** The individual features are each weak, but jointly they capture enough information to predict mergeability. A multivariate model should recover the distributed signal.

2. **Interpretation B (Feature Insufficiency):** The current feature family is fundamentally incomplete. The information needed to predict expert mergeability is not present in any combination of these features, and new features must be engineered.

Experiment 1.5 is designed to distinguish between these two interpretations. If a simple linear model achieves high prediction accuracy using the existing features (Interpretation A), no new features are needed and CARE can proceed directly to deployment. If a substantial linearization gap exists, or if even nonlinear models fail to achieve adequate prediction quality (Interpretation B), then Experiment 2—new feature engineering—is necessary.

---

# 3. Hypothesis

**Alternative Hypothesis (H₁):** The existing seven pre-merge proxy features, when combined through multivariate regression, achieve a Spearman rank correlation ρ ≥ 0.80 with Oracle KL divergence, and the linearization gap Δ = ρ_tree − ρ_linear ≤ 0.05.

**Null Hypothesis (H₀):** The combined feature set fails to achieve ρ ≥ 0.80 under any model family, or the linearization gap exceeds 0.05, indicating that the current features are representationally insufficient.

**Decision Criterion:**
- If ρ_linear ≥ 0.80 and Δ ≤ 0.05 → **Outcome A:** Existing features suffice; proceed to Experiment 3 (integration).
- If ρ_linear < 0.80 or Δ > 0.05 → **Outcome B:** Features are insufficient; proceed to Experiment 2 (new feature engineering).

# 4. Experimental Design

## 4.1 Dataset

The raw data consists of 16,112 expert-pair evaluations generated by Experiment 1 ([CARE_MoE_V3_E1.py](file:///Users/deepeshkumarjha/Desktop/CARE-MoE/Experiments-V3/CARE_MoE_V3_E1.py)). Each row corresponds to a unique (Layer, Expert_A, Expert_B, Seq_Len) combination. The model under study is **OLMoE-1B-7B**, a Mixture-of-Experts transformer with 64 experts per MoE layer across 16 MoE layers.

## 4.2 Preprocessing and Filtering

- **Sequence length filter:** Only rows with `Seq_Len = 256` are retained. This is the largest completed calibration size and provides the most stable oracle signal. This yields **4,016 rows**.
- **Layer filter:** Only `first` (layer 0) and `middle` (layer 8) are present in the Seq_Len=256 slice. The `last` layer data exists at other sequence lengths but is not included in this analysis.

## 4.3 Train/Test Split: Strict Disjoint Expert Split

Standard random splitting would allow the same expert to appear in both training and testing, creating identity leakage. Instead, we implement a **strict disjoint expert split**:

- **Training experts:** Indices 0–31 (32 experts)
- **Testing experts:** Indices 32–63 (32 experts)

Any pair (Expert_A, Expert_B) where one expert falls in the training set and the other in the testing set is **discarded** to prevent cross-boundary information leakage.

**Split statistics:**
| Partition | Count | Percentage |
|---|---|---|
| Training | 992 | 24.7% |
| Testing | 976 | 24.3% |
| Discarded (cross-boundary) | 2,048 | 51.0% |

The high discard rate (51%) is an unavoidable cost of preventing identity leakage. This is methodologically preferable to artificially inflated test metrics.

## 4.4 Normalization

**RobustScaler** (fitted on training data only) is applied to all features. RobustScaler uses median and interquartile range, making it resistant to the heavy-tailed distributions common in expert similarity metrics.

## 4.5 Reproducibility

- Random seed: 42
- All random number generators (NumPy, scikit-learn, XGBoost) are seeded deterministically.
- Configuration is centralized in [config.py](file:///Users/deepeshkumarjha/Desktop/CARE-MoE/Experiments-V3/experiments/experiment1_5/config.py).

# 5. Model Architecture

Four regression families are trained across three feature variants, yielding 12 models total.

## 5.1 Feature Variants

| Variant | Features | Count | Description |
|---|---|---|---|
| **A (Global)** | 7 pre-merge proxy features | 7 | Baseline feature set |
| **B (+Depth)** | Variant A + Relative_Depth | 8 | Tests whether layer position improves prediction |
| **C (+Interactions)** | Variant B + all pairwise feature × depth interactions | 15 | Tests whether feature-depth interactions capture layer-conditional effects |

Relative_Depth is computed as layer_index / (total_layers − 1), mapping `first → 0.0`, `middle → 0.533`, `last → 1.0`.

## 5.2 Models

### Linear Regression (OLS)
- **Algorithm:** Ordinary least squares
- **Hyperparameters:** None (closed-form solution)
- **Purpose:** Unregularized baseline; reveals overfitting sensitivity

### Ridge Regression
- **Algorithm:** L2-regularized least squares
- **Hyperparameters:** α = 1.0
- **Purpose:** Stabilizes coefficient estimates under multicollinearity

### LASSO
- **Algorithm:** L1-regularized least squares
- **Hyperparameters:** α = 0.0001, max_iter = 50,000
- **Purpose:** Performs automatic feature selection by driving irrelevant coefficients to zero

### XGBoost
- **Algorithm:** Gradient-boosted decision trees
- **Hyperparameters:**
  - n_estimators = 500
  - max_depth = 6
  - learning_rate = 0.05
  - subsample = 0.8
  - colsample_bytree = 0.8
  - reg_alpha = 0.1 (L1)
  - reg_lambda = 1.0 (L2)
- **Purpose:** Nonlinear baseline; captures feature interactions and threshold effects that linear models cannot

All models predict the continuous target **Oracle_KL** (KL divergence between original and merged model output distributions).

# 6. Feature Engineering

## 6.1 Pre-Merge Proxy Features (Used)

All seven features below are computed from the original model **before** any expert merging occurs. They require only the original expert weights, activations, and router outputs.

| Feature | Definition | Intuition |
|---|---|---|
| **Weight_Distance** | $\|\mathbf{w}_i - \mathbf{w}_j\|_2$ (L2 norm of flattened weight difference) | Large weight distance → experts learned different functions → merge is destructive |
| **Weight_Cosine** | $\frac{\mathbf{w}_i \cdot \mathbf{w}_j}{\|\mathbf{w}_i\| \|\mathbf{w}_j\|}$ (cosine similarity of weight vectors) | Directional alignment of expert parameters; high cosine → similar function |
| **Activation_Similarity** | Cosine similarity of expert activation vectors on calibration data | Measures whether experts produce similar intermediate representations |
| **Output_Similarity** | Cosine similarity of expert output vectors on calibration data | Measures functional similarity at the output level |
| **Routing_Similarity** | Cosine similarity of token routing probability vectors | Measures whether the router assigns similar tokens to both experts |
| **Usage_Frequency** | Sum of top-1 routing counts for both experts | Proxy for expert utilization; rarely-used experts may be safer to merge |
| **Jaccard_Overlap** | $\frac{|S_i \cap S_j|}{|S_i \cup S_j|}$ (Jaccard index of routed token sets) | Measures overlap in the sets of tokens each expert processes |

## 6.2 Oracle-Only Features (Excluded)

During the initial implementation of Experiment 1.5, six additional features were included that appeared to be pre-merge descriptors. Upon careful code audit, all six were found to be computed **inside the oracle merge-and-evaluate loop** ([run_oracle_pair](file:///Users/deepeshkumarjha/Desktop/CARE-MoE/Experiments-V3/CARE_MoE_V3_E1.py#L227)), requiring both expert merging and a second forward pass:

| Feature | Why Oracle-Only |
|---|---|
| CrossEntropy_Delta | Difference in CE loss between merged and original model |
| Hidden_L2_Drift | L2 distance of MoE hidden states between merged and original |
| Router_Entropy_Orig | Router entropy measured during oracle evaluation forward pass |
| Router_Entropy_Merged | Router entropy under merged configuration |
| Top1_Routing_Agreement | Top-1 routing agreement between original and merged models |
| TopK_Routing_Agreement | Top-K routing agreement between original and merged models |

**This is a significant scientific finding.** CrossEntropy_Delta in particular was initially the dominant predictor, inflating linearization gap estimates. Its removal nearly doubled the true gap, revealing that the existing pre-merge features are substantially weaker than preliminary results suggested.

**Scientific implication:** CARE is designed to be a lightweight pre-merge capability estimator. Including features that require the actual merge defeats the purpose. The distinction between *pre-merge proxy features* and *oracle-grade features* is a fundamental design constraint of the CARE framework.

## 6.3 Derived Features

- **Relative_Depth** (Variant B, C): Normalized layer position ∈ [0, 1]
- **Interaction terms** (Variant C): All products feature_i × Relative_Depth, adding 7 interaction features for a total of 15

# 7. Experimental Pipeline

1. **Data Ingestion:** Load 16,112 rows from [output.json](../exp1/output.json).
2. **Filtering:** Retain only Seq_Len = 256 → 4,016 rows.
3. **Expert Split:** Assign experts 0–31 to train, 32–63 to test. Discard cross-boundary pairs → 992 train, 976 test, 2,048 discarded.
4. **Feature Selection:** Extract 7 pre-merge proxy features + Oracle_KL target.
5. **Normalization:** Fit RobustScaler on training features; transform both splits.
6. **Feature Variant Construction:** Build Variants A (7 features), B (8), C (15) for both train and test.
7. **Model Training:** Fit 4 models × 3 variants = 12 models on training data.
8. **Evaluation:** Compute Spearman ρ, Pearson r, MAE, RMSE, R² on test data.
9. **Linearization Gap:** Δ = best_tree_ρ − best_linear_ρ.
10. **Feature Analysis:** Extract LASSO coefficients, XGBoost gain importance, SHAP values.
11. **Visualization:** Generate 7 publication-quality figures (300 DPI).
12. **Report Generation:** Automated decision logic produces the final recommendation.

---

# 8. Evaluation Metrics

| Metric | Definition | Rationale |
|---|---|---|
| **Spearman ρ** | Rank correlation between predicted and actual Oracle KL | Primary metric. Expert merging is a **ranking problem**: we need to identify which pairs are safest to merge, not predict exact KL values. Spearman is invariant to monotonic transformations and robust to outliers. |
| **Pearson r** | Linear correlation between predicted and actual values | Measures linear association strength. Discrepancy with Spearman indicates nonlinear relationships. |
| **MAE** | Mean absolute error | Scale-interpretable error magnitude |
| **RMSE** | Root mean squared error | Penalizes large prediction errors more heavily |
| **R²** | Coefficient of determination | Fraction of variance explained. Negative R² indicates the model is worse than predicting the mean. |
| **Linearization Gap (Δ)** | best_ρ(XGBoost) − best_ρ(Linear) | Quantifies how much predictive information exists in nonlinear feature interactions that the current feature representation cannot capture linearly |

## 9.2 Linearization Gap

| Quantity | Value |
|---|---|
| Best Linear Model | LASSO_A |
| Best Linear ρ | 0.484 |
| Best Tree Model | XGBoost_B |
| Best Tree ρ | 0.593 |

The gap of +0.109 exceeds the 0.05 threshold defined in H₁, and both models fall well below ρ = 0.80.

## 9.3 Interpretation

**Three critical observations emerge:**

1. **Absolute performance is poor.** The best model achieves ρ = 0.593—better than any individual feature (best univariate: Weight_Distance at ρ = −0.578) but far below the threshold needed for practical mergeability prediction. The best R² is 0.037 (LASSO_A), meaning the features explain less than 4% of the variance in Oracle KL.

2. **The linearization gap is large.** At Δ = +0.109, XGBoost extracts substantially more information than any linear model. This indicates the features contain nonlinear interaction structure that is not captured by the raw feature representation. However, even XGBoost's ρ = 0.593 is inadequate, meaning the features themselves—not just their functional form—are insufficient.

3. **Adding depth and interactions hurts linear models.** Variant B (ρ = 0.233–0.430) and Variant C (ρ = 0.194–0.406) perform worse than Variant A (ρ = 0.476–0.484) for all linear models. The unregularized models (OLS, Ridge) collapse severely when depth is added. Only LASSO survives by zeroing out harmful features. This suggests that depth interacts with the features in complex, nonlinear ways that linear models cannot capture.

# 10. Figure Analysis

## 10.1 Feature-Target Correlation Matrix

![Feature-Target Correlation Matrix (Training Set)](figures/01_correlation_heatmap.png)

The Pearson correlation heatmap reveals several important structural properties:

**Target correlations are weak.** The bottom row shows Pearson correlations between each feature and Oracle_KL. The strongest correlation is Usage_Frequency (r = +0.23), followed by Weight_Distance (r = −0.22). All other features have |r| ≤ 0.07, confirming the Experiment 1 finding that individual features are poor predictors.

**Multicollinearity exists in two clusters.** Weight_Cosine and Output_Similarity are highly correlated (r = 0.79), as are Routing_Similarity and Jaccard_Overlap (r = 0.79). This collinearity means these feature pairs carry largely redundant information, explaining why LASSO assigns near-zero coefficients to one member of each pair.

**Activation_Similarity is isolated.** It shows near-zero correlation with every other feature and with the target (r = −0.07). This feature appears to measure a genuinely independent aspect of expert behavior, but one that is uninformative for mergeability prediction.

**The correlation structure is sparse.** Most off-diagonal entries are near zero, indicating that the seven features capture largely orthogonal aspects of expert similarity. Despite this favorable property, their collective predictive power remains low.

## 10.2 LASSO Coefficients

![LASSO Coefficients (α = 0.0001)](figures/02_lasso_coefficients.png)

LASSO with α = 0.0001 retains all 7 features but assigns highly asymmetric magnitudes:

| Feature | LASSO Coefficient | Direction |
|---|---|---|
| Weight_Distance | −0.002283 | Larger distance → lower Oracle KL (counterintuitive; see below) |
| Output_Similarity | −0.001268 | Higher output similarity → lower Oracle KL |
| Usage_Frequency | +0.001139 | Higher joint usage → higher Oracle KL |
| Jaccard_Overlap | +0.000284 | Higher overlap → slightly higher Oracle KL |
| Activation_Similarity | −0.000176 | Near-zero contribution |
| Routing_Similarity | −0.000155 | Near-zero contribution |
| Weight_Cosine | +0.000017 | Effectively zeroed out |

**Key insight:** Weight_Distance dominates LASSO with a negative coefficient. This does not mean closer experts merge worse. Rather, after RobustScaler normalization and conditioning on other features, Weight_Distance captures residual variance not explained by the other features. The sign reflects the conditional relationship, not the marginal one. The marginal Spearman correlation of Weight_Distance with Oracle_KL is −0.578, consistent with the intuition that closer experts merge better.

**Feature selection:** Although no features are exactly zeroed, Weight_Cosine (0.000017) and Routing_Similarity (−0.000155) are effectively eliminated, consistent with their high collinearity with Output_Similarity and Jaccard_Overlap respectively.

**Feature importance is more uniform in XGBoost** than in LASSO. While LASSO concentrates weight on 2–3 features, XGBoost uses all features with more balanced importance. This confirms that the features interact in complex ways that reward nonlinear combination.

## 10.4 SHAP Feature Importance

![SHAP Feature Importance](figures/03b_shap_importance.png)

SHAP values (mean absolute) provide a model-agnostic measure of actual contribution to XGBoost_B predictions:

| Rank | Feature | Mean |SHAP| |
|---|---|---|
| 1 | **Weight_Distance** | 0.00105 |
| 2 | Jaccard_Overlap | 0.00098 |
| 3 | Output_Similarity | 0.00095 |
| 4 | Routing_Similarity | 0.00072 |
| 5 | Usage_Frequency | 0.00035 |
| 6 | Activation_Similarity | 0.00030 |
| 7 | Weight_Cosine | 0.00018 |
| 8 | Relative_Depth | 0.00015 |

**SHAP and gain importance disagree on the role of Relative_Depth.** Gain ranks it #1 (0.220) but SHAP ranks it last (0.00015). This is a well-known phenomenon: gain measures how often a feature is used for splitting (frequency × improvement), while SHAP measures the *marginal contribution* to each prediction. Relative_Depth is used in many splits (high gain) but each individual contribution is small (low SHAP) because it acts primarily as a *conditioning variable* that modulates the effect of other features.

**SHAP confirms Weight_Distance as the single most important predictor**, consistent with both its univariate Spearman correlation (−0.578) and its LASSO coefficient magnitude. Jaccard_Overlap and Output_Similarity follow, forming a clear top-3 feature group.

## 10.5 Predicted vs Actual Scatter

![Predicted vs Actual — XGBoost_B (Spearman ρ = 0.5927)](figures/04_predicted_vs_oracle.png)

The predicted-vs-actual scatter for XGBoost_B reveals severe pathologies:

1. **Compression toward the mean.** Most predictions cluster in the range [0.001, 0.006] regardless of the true Oracle KL value. The model fails to predict values above ~0.006, despite the test set containing Oracle KL values up to 0.024.

2. **Systematic underestimation of high-drift pairs.** Points in the upper-right quadrant (high actual KL) are consistently predicted far below the diagonal. The most extreme outlier has actual Oracle KL ≈ 0.027 but is predicted at ≈ 0.005.

3. **The ρ = 0.59 is driven by rank ordering within the low-drift majority**, not by accurate prediction of the critical high-drift tail. This is problematic because the high-drift pairs are precisely the ones that must be identified and avoided during merging.

4. **Negative R² (−0.507)** confirms the model is worse than predicting the mean for absolute value prediction.

## 10.6 Residual Analysis

![Residuals — XGBoost_B](figures/05_residual_plot.png)

The residual plot exhibits a strong **heteroscedastic fan pattern**:

- The most extreme negative residuals (−0.025) occur for the highest-predicted pairs, which have actual Oracle KL far exceeding the model's prediction range.

This pattern is diagnostic of a model that has learned the central tendency of the target distribution but lacks features to distinguish the tail behavior. The fan shape suggests that **a missing variable drives the variance** in Oracle KL, particularly for high-drift pairs.

# 12. Error Analysis

## 12.1 Distribution of Oracle KL

The target distribution is severely right-skewed:
- **Training set:** mean = 0.00460, std = 0.00607, range = [0.00055, 0.04271]
- **Test set:** mean = 0.00367, std = 0.00241, range = [0.00064, 0.02365]

The coefficient of variation (CV) is 132% for training and 66% for testing. The test set has a narrower range and lower variance, likely because experts 32–63 have different distributional properties than experts 0–31.

## 12.2 Failure Modes

1. **Tail blindness.** All models fail catastrophically for Oracle KL > 0.01. These high-drift pairs—the most critical ones for safe merging decisions—are systematically predicted as moderate-drift. This is the most serious practical limitation.

2. **Mean regression.** With R² near zero, both linear and nonlinear models default to predicting near the training mean. The modest Spearman ρ is achieved by correctly ordering the *relative* rankings of low-to-moderate drift pairs, not by accurate absolute prediction.

3. **Train-test distribution shift.** The train and test expert populations have different Oracle KL distributions (mean: 0.00460 vs 0.00367), reflecting genuine inter-expert-group heterogeneity. This is unavoidable under the disjoint expert split but reduces apparent model performance.

## 12.3 Variance Decomposition

The near-zero R² across all models indicates that Oracle KL variance is dominated by factors not captured in the current feature set. The residual variance is approximately equal to the total variance, meaning:

$$\text{Var}(\text{Oracle KL} \mid \text{features}) \approx \text{Var}(\text{Oracle KL})$$

This is the strongest evidence that new features are needed.

# 13. Scientific Findings

**Finding 1: Multivariate combination improves over individual features, but remains insufficient.**
The best individual feature (Weight_Distance, ρ = −0.578) is surpassed by multivariate LASSO (ρ = 0.484 after proper disjoint split) only modestly in the linear regime, and by XGBoost (ρ = 0.593) in the nonlinear regime. The improvement from univariate to multivariate is marginal, indicating that the features contain limited complementary information.

**Finding 2: The linearization gap is large (Δ = +0.109).**
XGBoost extracts 22.5% more rank correlation than the best linear model by exploiting nonlinear feature interactions, particularly depth-dependent effects. This gap represents information that exists in the current features but is inaccessible to linear models.

**Finding 3: Oracle-grade features must be distinguished from pre-merge features.**
Six of the thirteen originally considered features—including CrossEntropy_Delta, which was the dominant predictor—require the actual merge operation and cannot serve as pre-merge proxies. Their removal is scientifically critical and nearly doubled the measured linearization gap.

**Finding 4: Depth acts as a nonlinear modulator, not a linear predictor.**
Relative_Depth ranks #1 in XGBoost gain importance but provides zero improvement (or negative) to linear models. Expert mergeability depends on layer position, but this dependency is nonlinear and cannot be captured by additive depth terms.

**Finding 5: The current features cannot predict high-drift pairs.**
All models suffer from systematic underestimation of Oracle KL for high-drift pairs (>0.01). The features lack the information needed to distinguish dangerous merges from safe ones in the critical tail of the distribution.

**Finding 6: R² is near zero for all models.**
Even the best model (LASSO_C, R² = 0.070) explains only 7% of Oracle KL variance. The features are weak absolute predictors despite providing modest ranking information.

**The null hypothesis (H₀) is not rejected. The alternative hypothesis (H₁) is rejected.**

The conditions for H₁ required:
- ρ_linear ≥ 0.80 → **Observed: 0.484 (FAILED)**
- Δ ≤ 0.05 → **Observed: 0.109 (FAILED)**

Both criteria fail by wide margins. The existing seven pre-merge proxy features are representationally insufficient for predicting expert mergeability, whether combined linearly or nonlinearly.

# 15. Limitations

## 15.1 Dataset Limitations
- **Single model architecture.** All results are from OLMoE-1B-7B. Generalization to other MoE architectures (Mixtral, DeepSeek-MoE, Switch-Transformer) is untested.
- **Single calibration size.** Only Seq_Len=256 is analyzed. The feature-target relationship may differ at other calibration sizes.
- **Two layers only.** The Seq_Len=256 data covers only `first` and `middle` layers; `last` layer behavior is uncharacterized.
- **Disjoint split discards 51% of data.** The strict split is methodologically necessary but substantially reduces effective sample size.

## 15.2 Feature Limitations
- **All features are symmetric.** Every feature is invariant to the ordering of (Expert_A, Expert_B). Asymmetric features (e.g., magnitude imbalance) may carry additional signal.
- **No higher-order statistics.** Features are computed from first-order statistics (means, cosine similarity). Distributional features (e.g., Jensen-Shannon divergence of routing distributions) may capture richer information.
- **No capacity-aware features.** None of the features measure expert specialization or capability scope.

## 15.3 Model Limitations
- **No hyperparameter optimization.** XGBoost hyperparameters are manually specified, not tuned via cross-validation. Performance may improve with systematic tuning, though this would not address the fundamental feature insufficiency.
- **No ensemble methods beyond XGBoost.** Random forests, neural networks, or kernel methods are not evaluated.

## 15.4 Threats to Validity
- **Expert identity confounding.** Despite the disjoint split, experts 0–31 and 32–63 may have systematically different properties induced by training dynamics, introducing distribution shift.
- **Small effect sizes.** The absolute Oracle KL values are small (mean ≈ 0.004), making signal-to-noise ratios unfavorable.
- **Potential information leakage through layers.** Both train and test sets contain data from the same layers, meaning layer-level statistics are shared.

# 16. Conclusion

Experiment 1.5 provides definitive evidence that the current seven pre-merge expert similarity features are insufficient for predicting expert mergeability in Mixture-of-Experts language models. The best linear model (LASSO) achieves a Spearman rank correlation of only ρ = 0.484 with Oracle KL divergence, explaining less than 4% of target variance (R² = 0.037). Even the best nonlinear model (XGBoost) reaches only ρ = 0.593 with negative R², indicating that the features lack the representational capacity to predict merge quality.

The linearization gap of Δ = +0.109 confirms that nonlinear interactions between features—particularly depth-dependent effects—contain predictive information that the raw features cannot express linearly. However, even exploiting this nonlinear structure is insufficient, indicating that the fundamental problem is feature insufficiency rather than model insufficiency.

A critical methodological finding is the distinction between pre-merge proxy features and oracle-grade features. Six features initially included in the analysis—most notably CrossEntropy_Delta—were discovered to require the actual expert merge operation, violating the CARE framework's requirement for lightweight pre-merge estimation. Their removal is essential for the scientific integrity of the framework.

**Practical implication:** The CARE framework cannot proceed to deployment (Experiment 3) with the current feature set. New capability-aware features must be engineered that make the nonlinear predictive structure accessible to simple linear models.

**Theoretical implication:** Expert mergeability appears to be a complex, emergent property that is not fully characterized by pairwise weight similarity, activation similarity, or routing statistics alone. The high-drift tail of the Oracle KL distribution—the most critical regime for safe merging—is particularly poorly predicted, suggesting that the current features miss a fundamental aspect of expert capability.

# 17. Next Experiment

## Experiment 2: Capability-Aware Feature Engineering

### Research Question
Can newly designed capability-aware features reduce the linearization gap, enabling a simple linear model to approach the nonlinear prediction ceiling?

### Motivation
Experiment 1.5 established that:
1. The current 7 features achieve only ρ_linear = 0.484.
2. XGBoost reaches ρ = 0.593, revealing a gap of +0.109.
3. Depth-feature interactions are the primary source of nonlinear signal.
4. High-drift pairs are systematically mispredicted.

New features should target these specific deficiencies.

### Hypothesis
Augmenting the feature set with capability-aware descriptors will raise ρ_linear to within 0.03 of ρ_tree, closing the linearization gap without requiring complex nonlinear models.

### Candidate Features

| Feature | Definition | Rationale |
|---|---|---|
| **Output Magnitude Asymmetry (Δ_mag)** | $\|\ \|\mathbf{o}_i\| - \|\mathbf{o}_j\|\ \|$ | Asymmetric magnitude may predict asymmetric merge damage |
| **Routing Jensen-Shannon Divergence** | $\text{JSD}(p_i \| p_j)$ over token routing distributions | Distributional difference captures more than cosine similarity |
| **Routing NPMI** | Normalized pointwise mutual information of co-routing events | Measures whether tokens routed to expert i are also routed to expert j beyond chance |
| **Capability Drift Descriptors** | Per-token statistics of output magnitude change | Captures distributional properties of capability preservation |
| **Expert Specialization Index** | Entropy of routing distribution for individual experts | Measures whether experts are generalists or specialists |

### Expected Outcome
A linear model using the augmented feature set achieves ρ ≥ 0.70, and the linearization gap shrinks to Δ ≤ 0.03.

### Success Criterion
ρ_linear(new features) ≥ ρ_tree(old features) = 0.593

If a simple linear model with new features matches or exceeds what XGBoost achieves with old features, the new features have successfully captured the nonlinear structure in an interpretable, computationally efficient form.

### Potential Risks
- New features may be correlated with existing features, providing minimal incremental information.
- The irreducible noise floor may be higher than ρ = 0.70, limiting achievable performance regardless of features.
- Distributional features may require more calibration data than currently available (N=256).
